## High

### H-1 Next.js advisories (fixed on this branch)
`npm audit --omit=dev` now reports three advisories against `next` >=16.0.0 <=16.4.0. On 16 October there were none.
- GHSA-2464-fhr4-w9xw (critical): unauthenticated RCE in the Image Optimization API when SVG files are used.
- GHSA-673q-mjm6-r5xr (critical): unauthenticated RCE in `use cache` functions returning typed arrays.
- GHSA-p3m5-59mp-jv5r (high): denial of service in the App Router through Server Actions.

How exposed the site is:
- The site uses no `next/image` and no `use cache`. It has no `"use server"` actions either.
- The `/_next/image` endpoint still exists by default, and `public/` has SVG files. On Vercel, image optimisation runs on
  Vercel's side, so the real exposure is probably small. It could not be ruled out from here, so it is treated as live.

**Fix:** `next` and `eslint-config-next` are pinned at 16.4.2, the first fixed release on npm (published 15 Oct). The
lockfile change touches only `next`, `@next/*` and `eslint-config-next`. `next typegen`, `tsc`, `eslint`, a full
`next build` and the site tests all pass on it. It takes effect only once merged and deployed.

## Low

### L-1 Call it signs up any address (founder)
`/api/call-it` saves a guess for any email address and adds it to the Morning list through `joinMorning`. That sends
the welcome email at once, just as the newsletter form does (13 Oct M-4, single opt-in, still open). Once the result is
in, `/api/send/call-it` also sends that address one score email per round entered. So someone can make a stranger's
inbox receive the welcome email and a score email per weekly round.

Limits in place:
- 8 entries per 10 minutes per IP (per instance).
- One guess per address per auction. A second entry replaces the first, so one score email per round at most.
- 2,000 entries an hour overall, and the database caps welcome emails.
- No address is ever returned by the public board (`af_call_it_board`). Handles appear only if the reader opts in, and
  are limited to `[A-Za-z0-9 _.-]{2,24}`.

**Founder:** fold this into the M-4 decision. If the Morning becomes double opt-in, Call it should follow it, either by
sending score emails only to confirmed addresses or by confirming the address before the first score email.

### L-2 Shillings found counter integrity (accepted)
`/api/found` counts a result only when `Sec-Fetch-Site` is `same-origin` (or the `Origin` matches) and the request
is not a bot or internal call. It recomputes the difference from our own data, checks a fixed cap and counts one result
per page-view id per tool. A script can forge those headers and new page-view ids, though. Two limits still apply: 40 counts a
minute per instance, and in the database 5,000 a day per tool, market and currency, each within the cap. That is enough
to move the public total noticeably over a day. No personal data and no money are involved. This is accepted as a known
limit of an anonymous counter. If the total is ever quoted externally, a lower daily cap in `af_found_add` is the
lever.

### L-3 `uuid` via `exceljs` (accepted)
Unchanged since 16 Oct (L-3): the fix offered downgrades `exceljs` to 3.4.0, and the affected functions are not used.
The gray-matter/js-yaml chain accepted on 13 Oct (L-7) no longer shows in the audit.

### I-2 New code reviewed, no issues
- **Migrations 0042 to 0046:**
  - Every SECURITY DEFINER function pins `search_path = public`.
  - Every writer and every reader of addresses checks the `cron` secret from `af_secrets`. These are
    `af_rate_alert_create`, `af_rate_alerts_live`, `af_desk_signals`, `af_call_it_guess`, `af_call_it_entries`,
    `af_call_it_mark_scored` and `af_found_add`.
  - The deliberately public ones take bounded input and return no personal data. `af_rate_alert_confirm` needs a
    32+ character token. `af_call_it_board` returns counts and opted-in handles. `af_found_total` returns totals.
    `af_event` accepts named events only, with a path regex.
  - The new tables `call_it_guesses` and `found_daily` have RLS on and no policies. `found_daily` also has its table
    grants revoked.
  - Check constraints bound every column, including the new `series` column.
  - 0042 is only partly applied in production (its header lists the statements still to run). That is an operational
    item, not a security one.
- **`/api/call-it`:**
  - `parseEntry` validates the email (200 characters at most), the rates (0 to 40) and the handle.
  - The close time comes from the server's ledger, never the browser. The database refuses guesses after the close.
  - Logs carry no address (`redactEmails`).
- **`/api/send/call-it`:**
  - Bearer secret, compared in constant time (`bearerOk`).
  - Each guess is claimed before its email goes, so nothing is sent twice.
  - Failures are redacted. The email HTML escapes every value (`esc`, `para`).
- **`/api/found`:** strict input parsing, a 2,000-byte body cap and a recompute on the server. Only the tool, market,
  currency and amount reach the database. Every outcome answers 204.
- **`/api/data/poverty-premium`:** `month` must match `^\d{4}-\d{2}$` before any file path is built. No traversal.
- **`/api/pilot`:** the only change is that no next step or date is set on the deal (D-034). Log lines are unchanged:
  domain and organisation only.
- **`/api/rate-alerts`:** series alerts are checked against `getSeries` before the database call.
- **Desk (trimmed 22 Oct):**
  - `/desk`, `/desk/citations` and `/desk/whatsapp` check the desk key with `af_desk` and return the key form or a 404
    without it. The `preview-empty` bypass works only when `NODE_ENV=development`.
  - `/api/desk` and the session route are unchanged.
  - Search misses shown on the desk are cleaned by `cleanSearch`, which drops anything with `@` or 6+ digits.
- **XSS:**
  - Charts are now SVG strings (`lib/charts/render.ts`) set through `dangerouslySetInnerHTML` in `BarChart`. Every
    label, value, note and aria text goes through `esc`, and colours are constants.
  - `/embed/chart/<slug>/<n>` escapes every field. Its tooltip script uses `textContent`. Its parameters are
    allow-listed by `generateStaticParams` with `dynamicParams = false`.
  - Every JSON-LD block still escapes `<`.
  - `/share` builds its target from a parsed, allow-listed spec (slug regexes, tile ids) and escapes `</script>`.
    There is no open redirect.
  - `/preview/receipt-card` returns 404 in production unless a flag is set.
  - `error.tsx` and `global-error.tsx` show only the digest.
- **Workflows:**
  - New: `indexnow.yml` (`contents: read`, no secrets) and `poverty-premium.yml` (`contents: write`, commits a data
    folder, no secrets).
  - The new "Send Call it scores" steps pass `AF_CRON_SECRET` through `env:`, never inline.
  - No `pull_request_target`. No untrusted input is interpolated into `run:`. No new artifacts.
  - `documents.yml` and `site-qa.yml` are now pinned to `ubuntu-24.04`.
  - Python installs in the new workflows are unpinned (`pytest`, `requests`). That is the open 13 Oct M-7.
