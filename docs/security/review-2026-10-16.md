## Medium

### M-1 Private documents through a workflow in a public repository (fixed)
`.github/workflows/documents.yml` (added in #140) took `url` and `name` as `workflow_dispatch` inputs. It printed that
page to PDF and uploaded it as a 7-day artifact named `private-document`. Per `OPERATIONS.md`, this was the path for
private packs. A private pack link is a signed bearer URL (`lib/watch-link.ts`) that works for 120 days.

The repository is **public**, which causes two problems:
- The step's `env:` (URL) is printed in the public run log, and so is any error message that names the URL.
- Any signed-in GitHub user can download artifacts on a public repo.

Exposure was checked: the one dispatched run (15 Oct) used no URL, and no `private-document` artifact exists. Nothing
leaked.

**Fix:** the inputs, the private step and the artifact upload are removed. The workflow now prints only the public
documents. Print private packs locally with `node scripts/make-documents.mjs --url <link> --name <name> --out <dir>`
(the header comment and `OPERATIONS.md` now say so). `tests/site/test_workflow_security.py` keeps it that way.

## Low

### L-1 `$GITHUB_ENV` written before validation (fixed)
In `.github/workflows/fixtures.yml`, `echo "FOLDER=$FOLDER" >> "$GITHUB_ENV"` ran before the `^[a-z0-9_-]+$` check. A
dispatch input with a newline could have added environment lines, though the job then failed at the check.
Only people with write access can trigger it.
**Fix:** the check now runs first, with a test.

### L-2 Personal data in the public repository (founder)
`docs/sales/pipeline-log.md` and `docs/strategy/partners-and-revenue.md` name individual contacts with their work
emails, next to sales notes. The addresses were taken from the firms' own contact pages, but outreach notes about
named people in a public repo sit badly with the Kenya Data Protection Act and GDPR minimisation.
**Founder:** decide whether `docs/sales/` and the contact parts of `docs/strategy/` belong in a public repo. Options
are moving them to a private repo or the desk, or keeping organisation names only. They also stay in git history.

### L-3 `uuid` via `exceljs` (accepted)
`exceljs` (added for the Excel downloads) pulls in `uuid` <11.1.1, which has a moderate advisory: a missing bounds check
in v3/v5/v6 when a `buf` is passed. The fix offered (`npm audit fix --force`) downgrades exceljs to 3.4.0, which is a
breaking change. The workbooks are built from our own data and do not call those functions. The lockfile is unchanged.
The other remaining advisories are gray-matter → js-yaml/argparse/sprintf-js, already accepted (2026-10-13 L-7). There
is no advisory against `next` 16.3.8.

### I-2 New code reviewed, no issues
- **`/downloads/session`:**
  - Same-origin check, 4 KB body cap, key shape checked before any database call, per-IP attempt limit.
  - The key is never logged or put in a URL.
  - The session cookie is HttpOnly, Secure and SameSite=Lax. It holds the key's hash, signed with HMAC-SHA256 under a
    domain-separated key, and is checked in constant time with a 12-hour maximum.
  - `next` passes through `safeNext`, which allows same-site paths only and rejects `//`, `/\` and control
    characters. There is no open redirect.
  - Gated CSVs served under a session are `private, no-store` with `Vary: Cookie`.
- **Analyst keys** go through the same `paidMonths` amount check as Team keys. `af_paid_key_issue` (0039) and
  `af_api_key_use_hash` check the cron secret.
- **`/watch/<slug>/<token>`:**
  - The HMAC is bound to the slug, with expiry and a revocation list, compared with `timingSafeEqual`.
  - Responses are `private, no-store`, `noindex` and `no-referrer`.
  - The desk pages that mint links (`/desk/watch`, `/desk/cases`, `/desk/design`) return 404 without the desk key.
- **Desk actions:**
  - `deal_quick`, `idea` and `inbox_handle` validate stage, ids, dates and lengths, and log nothing.
  - They sit behind `sameOrigin` and the database secret check.
  - Migration 0040's functions return null without the secret.
- **`/go/*`** still redirects only to allow-listed partner and fund URLs.
- **New redirects** (`parked` in `next.config.ts`) are static.
- **XSS:**
  - Every JSON-LD block escapes `<`. The only other inline script is the constant theme script.
  - `react-markdown` (Receipts, Markdown bodies) runs without `rehype-raw`.
  - The HTML documents (`pack-html`, `watch-html`, `documents/design`, index release) pass text through `esc`.
  - Registry source links are all `https:`.
- **Logging:** no new log lines carry emails or keys. `/api/hit` and `/go` skip internal calls and prefetches; the
  `x-afronomics-internal` header only affects counting.
- **Workflows:**
  - No `pull_request_target`.
  - `site-qa.yml` (the only `pull_request` trigger) has `contents: read` and no secrets.
  - New `contents: write` workflows (calls ledger, forecast ledger, registry, documents, fixtures) commit data only and
    hold no secrets except `GITHUB_TOKEN`.
  - No secret is interpolated into a `run:` script (now tested).
  - Python installs remain unpinned (2026-10-13 M-7, still open).
